# LOT 9 — Internationalisation (i18n)

> Objectif : rendre la plateforme **prête pour le multilingue**. Ajouter une langue doit
> se résumer à **ajouter un fichier de traduction par appli et l'activer dans une liste**,
> sans toucher au code. Aujourd'hui, **seul le français est actif** : l'interface est
> strictement identique à avant le lot.

Règle d'or, désormais permanente : **plus jamais de texte visible en dur** dans le code
(JSX, Kotlin/Compose, notifications…). Tout texte passe par le catalogue de l'appli.

---

## 1. Console parent (`apps/parent-web`)

### 1.1 Architecture

Module maison, typé, **sans dépendance** : `src/i18n/`.

| Fichier | Rôle |
|---------|------|
| `config.ts` | `SUPPORTED_LOCALES` (**seule liste à éditer** pour activer une langue), `DEFAULT_LOCALE = "fr"`, `RTL_LOCALES = ["ar", "he", "fa", "ur"]`, résolution de la langue initiale. |
| `locales/fr.ts` | Catalogue **source** (objet imbriqué par domaines : `app`, `common`, `nav`, `dashboard`, `login`, `views.<vue>`, `errors`, `enums`, `audit`, `units`…). |
| `types.ts` | Type `Messages` **dérivé de `fr`** ; clés pointées typées (`MessageKey`) ; paramètres `{nom}` déduits du texte français. |
| `core.ts` | État de langue, `t()` (interpolation, pluriels `Intl.PluralRules`), chargement paresseux des catalogues, mise à jour de `<html lang dir>` et du titre. |
| `format.ts` | `fmt.*` : dates, heures, nombres, durées, octets, temps relatif — **tout via `Intl.*`** avec la langue active. |
| `errors.ts` | `errorMessage(err)` : codes backend → `errors.*` (jamais de message brut affiché). |
| `I18nProvider.tsx` | Contexte React, hook `useI18n()` → `{ locale, setLocale, t, fmt }`, composant `<Trans>` (texte riche). |
| `index.ts` | Point d'entrée unique + `labelMap()` (tables de libellés relues dans la langue active). |

Résolution de la langue au démarrage (`main.tsx` attend `initI18n()` avant le premier
rendu, pour éviter un flash dans une autre langue) :

1. préférence enregistrée (`localStorage["cp.locale"]`, lue en try/catch) ;
2. langues du navigateur (`navigator.languages`), tag exact puis langue de base (`fr-CA` → `fr`) ;
3. `fr`.

Le français est embarqué dans le bundle principal (source et **repli** si une clé manquait
à l'exécution) ; chaque autre langue est un **chunk séparé** chargé à la demande
(`import.meta.glob`).

### 1.2 Utilisation dans le code

```tsx
const { t, fmt } = useI18n();                       // dans un composant
t("nav.overview");                                   // clé typée (erreur TS si inconnue)
t("views.requests.pendingCount", { count: n });      // pluriel : { one, other, … }
t("views.location.lastFix", { ago: fmt.ago(iso) });  // paramètre {ago} obligatoire (typé)
fmt.date(iso, { weekday: "short", day: "numeric" }); // jamais toLocaleString("fr-FR")
<Trans k="dashboard.noChild" tags={{ b: (c) => <b>{c}</b> }} />   // texte riche
setError(errorMessage(error));                       // jamais error.message
```

- **Hors React** (`lib/*`) : importer `t` / `fmt` depuis `src/i18n` ; ils lisent la langue courante.
- **Tables de libellés** exportées par `lib/*` (`GEOFENCE_TYPE_LABEL`, `FILTER_CATEGORIES`,
  `AGE_PRESETS[k].label`…) : construites avec `labelMap()` ou des *getters*, elles se relisent
  à chaque accès → elles suivent un changement de langue.
- **Ne jamais concaténer** des morceaux de phrase (l'ordre des mots change selon les langues) :
  une phrase = une clé, avec paramètres et balises.
- **Erreurs** : `errorMessage(err)` reconnaît les codes des RPC/Edge Functions
  (`unauthenticated`, `forbidden`, `invalid_name`, `missing_params`, `child_not_in_family`,
  codes d'appairage…), les codes Supabase Auth et PostgREST (`42501`, `23505`, `PGRST301`),
  les messages français historiques des RPC RGPD (« enfant introuvable », « accès refusé… »)
  et les erreurs réseau ; à défaut, message générique traduit (le détail part en console).
  Les fonctions `lib/*` qui renvoient `{ error: string | null }` renvoient déjà un message
  **traduit**.

### 1.3 Garde-fous (CI « Console parent (web) »)

- `npm run typecheck` : chaque catalogue se termine par `satisfies Messages` → **une clé
  manquante ou en trop fait échouer le build**. Les clés passées à `t()` et leurs paramètres
  sont vérifiés à la compilation.
- `npm run check:i18n` (`scripts/check-i18n.mjs`) : mêmes clés que `fr`, mêmes paramètres
  `{…}` et balises `<…>`, pluriels conservés, chaque langue active a son fichier, et aucune
  locale codée en dur (`"fr-FR"`, `toLocaleString("…")`) hors de `src/i18n`.

### 1.4 Ajouter une langue (pas à pas)

Exemple : l'espagnol (`es`).

1. Copier `src/i18n/locales/fr.ts` en `src/i18n/locales/es.ts`.
2. Dans `es.ts`, remplacer la fin du fichier :
   ```ts
   import type { Messages } from "../types";
   const es = { /* … textes traduits … */ } satisfies Messages;
   export default es;
   ```
   (retirer le `as const` du français : seul le catalogue source en a besoin).
3. Traduire **les valeurs** (jamais les clés). Conserver à l'identique les paramètres
   `{nom}` et les balises `<b>…</b>`. Pour les pluriels, fournir les formes CLDR de la langue
   (`one`/`other` en espagnol ; `zero`/`one`/`two`/`few`/`many`/`other` en arabe…).
4. Activer la langue : `SUPPORTED_LOCALES = ["fr", "es"]` dans `src/i18n/config.ts`.
5. `npm run typecheck && npm run check:i18n && npm run build`.

C'est tout : le sélecteur de langue (pied de la barre latérale) **apparaît automatiquement**
dès que deux langues sont actives, le nom de chaque langue est affiché dans sa propre langue
(`Intl.DisplayNames`), dates et nombres suivent la langue (`Intl.*`).

> Contenus **propres à la France** à adapter par pays plutôt que simplement traduire :
> `helpResources.*` (3018, 3114, PHAROS — numéros français) et les mentions RGPD/CNIL.

### 1.5 Sens d'écriture droite-à-gauche (RTL)

- Une langue listée dans `RTL_LOCALES` (arabe, hébreu, persan, ourdou) passe automatiquement
  `<html dir="rtl">`.
- La mise en page n'utilise que des **propriétés logiques** (`margin-inline-start/end`,
  `padding-inline-*`, `border-inline-start`, `inset-inline-*`, `text-align: start/end`),
  dans `styles.css` comme dans les styles inline (`borderInlineStart`…) : elle se retourne
  d'elle-même. Ne plus jamais écrire `left`/`right` (sauf coordonnées de pointeur/écran,
  ex. position d'infobulle).
- Les graphiques (barres, anneau) et la carte gardent leur orientation (axes temporels,
  géographie) ; seuls les libellés suivent la langue.
- **Test manuel** : dans les outils de développement, exécuter
  `document.documentElement.dir = "rtl"` : la barre latérale passe à droite, les listes,
  tableaux et cartes s'alignent à droite, les bandeaux à liseré (SOS, appels…) ont leur liseré
  côté droit ; `document.documentElement.dir = "ltr"` pour revenir.
